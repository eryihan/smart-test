# smart_test 使用指南

help 按主题说明用法；仅阅读帮助，不扫描项目或写文件。

按问题定位：[入口](#工作入口)、[控制项](#常用控制项)、[结果](#结果和产物)、[状态](#项目状态)、[更新](#更新-skill)、[卸载](#退出管理与卸载)。安装步骤属于宿主操作；本文件随 skill 分发，安装后仍可独立使用。

## 调用方式

Codex：`$smart-test <入口>`。Claude 插件：`/smart-test:<入口>`，兼容 `/smart-test:smart-test <入口>`。其他兼容宿主使用原生调用方式。也可直接说“补这次金额改动的测试”“评估现有测试体系”“更新 smart-test”。

当前专项为 Java/Spring、Maven/Gradle；其他技术栈按原生设施与通用方法评估，说明未验证的专项范围。

## 工作入口

| 入口 | 用途与默认行为 |
|---|---|
| help | 只读用法，不扫描项目 |
| init | 复用或补齐测试设施，形成必要长期约定，验证代表性测试 |
| scan | 按范围评估已有行为保护，默认分析全仓；不自动补完历史测试 |
| changes | 分析真实变更，授权内补强测试并验证 |
| check | 运行已有入口，检查报告与质量门，无需项目登记 |
| pipeline | 生成候选，分别验证命令、语法和 Runner；默认交付 patch |
| status | 只读当前规范、相关待办和必要近期证据，不运行测试或探测环境 |
| update | 沿原渠道更新安装包，保护定制，不处理业务项目 |
| uninstall | 交接项目能力与剩余事项，再沿原渠道卸载 |

局部任务无需先 init、创建正式规范或任务 ID。搭建和全仓优化可深入评估；日常任务只读相关范围。已有业务资料复用，无资料时恢复本次所需行为，不默认维护完整业务地图。

## 常用控制项

- `--dry-run` / 明确只读：只分析和对话交付，不写文件/锁、不构建、不启动服务或下载。
- `--staged` / `--base <ref>`：变更范围见 [workflows.md](workflows.md#changes)，实际测试版本另行核对。
- `--fast` / `--full`：控制验证范围，不更改已有质量门或排除风险必需测试。
- `--strict`：展示具体阶段选择，不制造整套产物或重复询问已有授权。
- `--auto`：复用已有约定和授权，未定业务结果与新授权仍须核对。

控制项由 Agent 解释，当前用户要求优先。

## 覆盖率

未指定时沿用已有门禁，不新增工具和数字阈值。可要求只报告、整体、增量或两者；增量需指定可靠基线。没有可执行变更行为 NOT_APPLICABLE，报告/映射/基线不可靠为 UNKNOWN。范围与公式见 [coverage.md](coverage.md)。覆盖率不能证明行为断言充分。

## 结果和产物

交付说明保护的行为、修改、真实命令、版本、测试计数、失败和未验证范围。分析完成、编译成功和测试通过分别报告；EVIDENCE_PASS/VALID 只是工具局部结果。必需 suite 缺失、跳过、零测试和陈旧证据不能完整 PASS。

长期约定维护项目现有生效规范，需要跨任务接续的缺口维护一个当前入口。证据优先使用原生报告/CI，必要时才保存快照。普通任务不生成整套画像、策略或阶段文件；Python 不可用时继续通过宿主工作。

资料触发更新、有限留存与清理见 [artifacts.md](artifacts.md)，执行见 [verification.md](verification.md)。

## 测试边界

规则用最低充分边界；SQL、事务、Redis/broker 语义使用对应隔离依赖。可控远程替身只证明本服务客户端处理，不证明 provider 实现。已有兼容框架优先保留，环境受阻继续独立工作。

明确业务规则与实现不符时，按规则补回归测试；只有预期未知或可信来源互相冲突时，才暂停依赖该预期的断言。预期来源与 characterization 的边界见 [用例设计](test-design.md#明确要保护的行为)。生产修改、正式 CI、外部消息和远端执行按实际授权处理。

## 典型请求

```text
$smart-test init --dry-run
$smart-test scan，只检查 order 模块，给出分批补测建议
$smart-test changes --base origin/main
$smart-test check --fast
$smart-test pipeline
$smart-test status
刚才这个测试建议不对，帮我整理反馈
```

## 反馈

直接说“刚才这个处理不对，帮我整理反馈”，即可获得可复制的脱敏说明；无需克隆维护仓库。版本、最小复现、来源渠道与可选附件按 [feedback.md](feedback.md) 处理，提交需要用户明确要求。

## 项目状态

读取已有规范和当前事项，只在解释具体结论时读取关联的近期报告/CI 或快照。列出必需项、已知执行结果、未完成范围与下一步；没有保存证据时说明未知，不补造历史。

不遍历全部历史来推导当前状态，不扫描全仓文档，不运行测试、Docker/DB 探测，不写文件/锁或清理。发现相关源码/配置/实际约定变化时说明需要复核；规范仅改措辞不自动失效。只有 Unit 证据时不能写全仓健康或 Integration 已通过。历史结果不等于当前验证。

## 退出管理与卸载

uninstall 先交接当前项目再卸载安装包；dry-run 只展示动作。用户只卸载安装包时遵守范围，不强制建规范或改项目。

1. 核对实际安装路径、渠道、ID 和范围。用户级卸载可能影响同安装的其他项目，说明范围，不扫描其他仓库；多个对象无法区分时询问准确对象。
2. 在现有规范/当前事项中补清运行入口、隔离前提、已验证范围与剩余工作。没有载体且确有交接信息时保存最小内容，不复制第二份手册，不要求重跑全量测试。
3. 检查测试、构建、fixture、脚本与正式 CI 对 skill 安装路径的实际依赖，优先改为原生入口；必要移入项目的工具保留许可证和维护说明，验证改动。未解除依赖时如实报告阻塞。
4. 保留成熟项目资产、有效约束、未完成事项、必要证据和用户修改；只移除明确属于本次安装的自动加载条目，不删除整份 AGENTS.md / CLAUDE.md。卸载不顺带清空历史；需清理时另按留存和迁移规则处理。
5. 沿原宿主管理器与范围卸载，不手删管理器缓存。支持保留数据时采用该选项；独立安装只移除确认的 skill 目录，保护未迁出的定制。项目交接与安装包移除分别报告成功、失败和下一步。

原生卸载没有交接钩子，项目从交付起应独立可用。重新安装先核对团队后续修改和未完成事项，继续维护，不重新搭建整套设施。

只移除 Claude 插件安装包时，可使用：

```bash
claude plugin uninstall smart-test@smart-test --keep-data
```

项目级操作增加 `--scope project`；`--keep-data` 保留插件自身的持久数据，不代替项目交接。Codex 独立安装只移除已确认的 skill 目录，保留项目测试资产。

## 更新 skill

用户可直接说“更新 smart-test”，也可按宿主调用：

```text
Codex:       $smart-test update
Claude 插件: /smart-test:update
独立 skill:  按宿主的调用方式请求 smart-test update
```

update 仅更新 skill，不改目标项目的测试框架、依赖、源码或 `.smart-test/`。`help update` 返回用法；`update --dry-run` 读取本地版本与来源并列出动作，不下载、不刷新缓存、不写文件。

执行 update 时：

1. 确认实际加载路径、version.json 和安装范围。用户指定来源与宿主管理记录优先，包内 source 仅作默认候选。保留 fork、私有源、分支和固定版本；来源冲突时列出差异并确认渠道。
2. 从原来源获取候选到临时目录，核对名称、版本、必要文件和引用。不自动降级；版本与文件均一致才判定无需更新，同版本内容变化仍须核对。
3. 用可靠旧基线识别本地定制；无基线时标明未知并完整备份。已知定制先给保留或合并方案，覆盖需授权。更新范围明确且无待定选择时直接继续。
4. 使用原宿主管理器，保留范围与 ID，禁止手工修改管理器缓存。独立目录先校验候选，再将旧目录备份到技能发现目录之外并替换；失败恢复旧目录。
5. 核对磁盘版本与文件，记录更新前后版本、来源、备份和重载状态。离线、权限受限或管理器失败时保留旧版本，报告已完成步骤。重载或新会话后确认宿主实际加载版本。成功更新后按项目/用户政策检查独立安装备份，仅在定制已承接且回退版本可靠时清理冗余；不清宿主管理器缓存。

Claude 默认市场安装示例：

```bash
claude plugin marketplace update smart-test
claude plugin update smart-test@smart-test
```

更新项目级安装时，第二条命令增加 `--scope project`。更新后重新加载插件或开启新会话。第三方市场默认不自动更新，需要时可在 `/plugin` 的 Marketplaces 页启用；自动更新后仍按宿主提示重载。

Codex 的 skill-installer 拒绝覆盖已有目录。先校验候选并备份旧目录，再按原来源安装，失败恢复；其他独立安装采用目录替换。源码/离线安装器的 `--replace` 会备份旧目录，执行前仍须检查定制。

旧版缺少 update 时，直接请求 Agent 更新或使用原管理器升级。用户获取的是已发布内容。参考：[Agent Skills](https://agentskills.io/specification)、[Claude 插件更新](https://code.claude.com/docs/en/discover-plugins#keep-plugins-updated)。
