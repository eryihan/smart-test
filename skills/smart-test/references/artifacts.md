# 项目资料与留存

项目资料只承担三种职责：生效测试约定、当前未完成事项、必要验证依据。优先使用项目已有文档、issue/待办、原生报告和 CI；不默认生成画像、策略、Oracle、阶段记录或状态账本。

## 生效规范

已有 testing-rules.md 等正式规范直接复用；init 或长期约定形成时才补充，无规范不阻止局部任务。沿用项目文档位置，需要新建时可用 docs/testing.md。记录测试边界、隔离、必要质量门及选择依据，命令尽量引用项目脚本或构建 task。业务资料引用原来源，不复制成平行业务地图。

测试相关 AGENTS.md / CLAUDE.md 可在授权范围内指向规范，不删除整份文件。已有业务文档与代码冲突时指出具体差异，不凭实现重写业务规则。一次性授权只在本次任务使用。规范文字变化由 Agent 判断是否影响要求；无需因措辞变化重跑。

## 当前事项与证据

确需跨任务接续时维护一个当前入口，优先使用已有待办或测试债务文档。没有载体时可用 docs/testing-work.md，不与历史记录各存一套当前状态。每项写行为/缺口、依据、未完成范围、解除条件及下一步；沿用已有编号。解决、取消或替代时说明依据并退出当前清单，必需验证未完成时仍保留。外部 issue 更新遵守用户授权，无法更新时交付具体内容。

普通计划留在当前任务，不创建独立阶段文件。扫描分区是工作视图，不默认长期维护完整业务版图。任务失败或中断时保存恢复所需的最小内容；不把“计划完成”当测试通过。

验证优先引用可信原生报告或 CI，列明实际命令、版本、环境、套件、计数和未验证范围。只有项目/用户要求，或报告会被覆盖、诊断与复核需要时，保存 `.smart-test/runs/<run-id>/manifest.json` 与必要快照。工具格式是事实交换格式，Agent 不为普通任务手工制造 manifest。源码和环境未被完整记录时，不能仅凭快照证明当前结果。

## 变化触发维护

| 本轮变化 | 接续动作 |
|---|---|
| 长期测试约定或执行入口变化 | 更新/核对规范相关段落与入口引用 |
| 发现解决、取消、替代或解除阻塞 | 更新对应当前事项，保留未完成必需验证 |
| 业务依据变化 | 重评相关断言、计划与结论 |
| CI 候选应用或取消 | 核对正式结果和剩余事项后处理候选 |
| 临时产物用途结束 | 按下述规则清理 |

交付前只核对本轮受影响内容，重新读取实际修改部分。只读任务仅指出问题。历史报告保留当时版本与事实，不随当前变化重写；对话结论与实际文件和执行结果一致。

## 有限留存

清理通过普通文件工具完成，先用目录时间、数量和大小筛选候选，再核对当前引用与候选归属；不逐份重读全部历史，也不在每个小任务中做全仓清理。项目政策优先。清理边界限于明确由 smart-test 生成管理的过程资料；正式文档、用户资料、原生构建目录和宿主缓存遵守各自约定。

- 临时输入使用结束即清理。CI 候选应用或取消后，在必要事实进入正式配置/当前事项后清理。
- 新保存的普通证据默认窗口：近 30 天、最多 20 次、合计 200 MiB；任一上限超出时处理最旧且无有效依赖的证据。项目已有政策优先。首次保存、后续保存超过窗口，或明确维护任务时检查；不为了日常查询清理。
- 未解决问题、当前必要验证和审计要求保护必要证据，不能仅按年龄删除。保护内容超出预算时报告具体原因与处理需求，不破坏证据或静默永久扩容。
- 正常清理前核对当前事项、正式文档和明确的审计引用。仍有追溯用途的结论保留紧凑结果与版本说明，注明原始证据已按政策清理；同类说明更新已有摘要，不逐次追加清理流水。摘要不能支持新的当前 PASS。意外缺失/损坏单独报告。
- 安装备份只在来源、定制与回退需求明确后处理；保留一个可靠回退版本。无可靠旧基线或未迁出的定制继续保护并说明，禁止直接按目录年龄删备份。

不另建无限归档或每次删除的独立报告。历史不参与当前状态的日常计算。安装包更新不自动迁移或删除项目资料。
