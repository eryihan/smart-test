# 使用现场反馈

仅在用户提出问题或要求整理反馈时使用。普通测试任务不产生反馈文件。

## 默认路径

用户可以直接说“刚才这个处理不对，帮我整理反馈”。Agent 从当前对话和实际结果组织一段可提交内容：

- 当时使用的 skill 版本、宿主与入口；未知项说明未知，不把升级后版本当旧版本。
- 合成场景、用户要求、实际行为、期望行为及其依据。
- 最小复现和未验证范围；没有复现时说明尚未复现。

隐去企业/项目/人员标识、源码、内部 URL、账户、凭证、原始日志和真实业务数据；用中性名称和合成数据表达。必要语义无法安全保留时说明需要合成复现，不假装脱敏内容足以定位。交付前复核文本。

读取实际安装来源与 version.json，提供对应反馈渠道。默认上游为 [GitHub Issues](https://github.com/eryihan/smart_test/issues)；fork/私有源按其实际渠道，不擅自把私有资料送给上游。用户复制即可，无需克隆维护仓库。发送、上传或创建 issue 需要明确授权；无连接能力时交付可复制文本。

## 可选诊断附件

只有工具问题需要统计且用户要求时，使用白名单 exporter。用户指定目标项目外的新目录；拒绝已有目录、遍历和符号链接，不自动上传：

```text
python3 <skill-dir>/scripts/export_feedback.py --repo <repo> --output <项目外新目录> --host codex --workflow check --run <相关run-id>
```

默认只输出 metadata.json、feedback.json、execution-summary.json；run 可重复，未指定时最多读取最近 100 个目录，明确省略数量。只读取选定运行的 manifest，不读取项目规范、待办或其他资料。未知输入不会为导出而补造。

版本来自安装包；宿主版本可显式提供数字，否则 null。脚本不读取源码、XML、日志、环境变量、目标 Git remote，不运行命令、测试、服务或网络。只输出白名单枚举、计数、布尔值与匿名编号，不复制命令参数、自由文本或原始标识。单文件最大 2 MB，列表最多 1000 项，包目录/文件使用本地受限权限。

附件只辅助定位，不作为项目当前状态或执行证据。最小反馈无需附件；原始导出包按维护者约定处理，不进入公开 Git。维护者再将脱敏问题转为回归场景；仅增加未执行场景不能证明修复。
